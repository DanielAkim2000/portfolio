# An ecosystem of five applications

Matunda is an investment app for African stocks (listed in Africa, Europe and elsewhere). I have been building it on my own, for my uncle, since February 2025. It grew from a simple mobile app into a real ecosystem of several independent repositories that share the same API contract:

- **The API (NestJS 11)**: the heart of the product, with Prisma 7, PostgreSQL and Redis
- **The mobile app (Expo / React Native)**: iOS and Android, for end users
- **The back-office (Next.js 16)**: for the team, with roles and permissions
- **The marketing website (Next.js 16)**: public pages, contact and launch waiting list, in ten languages including Arabic
- **Monitoring (Prometheus, Grafana, Alertmanager)**: knowing whether the API is healthy, and being alerted when it is not

More than 1,300 commits in total across these repositories.

---

# The API

The API is versioned, documented with Swagger and serves all three clients. It covers:

- **Market and assets**: prices, history, fundamentals, screener and stock search, with a Redis cache
- **Exchanges**: trading hours and holidays per market
- **Simulated trading**: buy and sell orders, portfolio, multi-currency wallet and transactions, with idempotency on orders and deposits. Money is virtual for now, and the design already plans for real accounts
- **News**: ingestion, deduplication, automatic translation and per-ticker sentiment analysis, with moderation
- **AI analyses**: stock analyses generated by an agent
- **Accounts and security**: sign-up with email verification, one-time-code login, access and refresh tokens, per-device sessions, data export and account deletion (GDPR), versioned terms acceptance
- **Notifications**: price alerts, push notifications and targeted campaigns from the back-office

# Mobile app and back-office

On mobile, users can search for a stock, open its page (price, history, fundamentals, analyses, news), follow watchlists, create price alerts and place simulated orders. The app is translated into French, English and several African languages, supports biometrics, and can show a maintenance screen or require an update, both driven by the backend.

The back-office never talks to the database directly: it calls the API, which enforces permissions. Each administrator has a role (super admin, support, finance, content), can enable two-factor authentication, and every action is recorded in an audit log. It also provides business reports (funnel, retention, volumes) and the health of scheduled jobs.

# What this project teaches me

- **Architecture**: splitting a product into several repositories around an API contract, and evolving it without breaking anything
- **Security**: authentication, roles and permissions, two-factor authentication, auditing, GDPR compliance
- **Performance and reliability**: caching, scheduled jobs, idempotency, monitoring and alerting
- **Industrialisation**: Docker, continuous integration, quality rules shared by every repository
- **Product**: serving a real need, with a real user
